01 / Evidence collection

What the Python script does

tools/gap_audit.py reads a source sitemap or URL list, maps each route to the target, and collects both pages. It extracts static HTML, compares content signals, checks unique internal destinations, and saves the evidence with a generated report.

  1. Freeze the scope. Deduplicate the inventory, apply inclusions and exclusions, and use explicit mappings for moved routes.
  2. Capture both sites. Save response status, redirects, timestamps and raw snapshots, plus titles, metadata, headings, text, links and image-alt signals.
  3. Compare and report. Calculate text similarity and heading/link-label coverage, check target links, and generate JSON plus a Markdown report.

The files you get

OutputWhat it tells you
evidence.jsonThe captured observations, effective configuration, inventory and page responses. Preserve this unchanged.
snapshots/Raw response bodies and inventory inputs, named by their SHA-256 hashes.
analysis.jsonComputed totals, denominators, per-page metrics, review flags, findings and evidence/review hashes.
reviews.jsonA finding register, initially empty, that a reviewer fills with supported findings tied to this evidence.
report.mdThe report generated from the saved evidence and any recorded review findings.

How to read the results

Content signals

Text similarity uses token-frequency cosine similarity. Heading and link-label coverage measure retained distinct labels. Scores below 90%, 90% and 95%, respectively, flag a difference for review.

Availability & counts

404/410 means unavailable at capture time. Timeouts, access blocks and other unsuccessful responses remain unverified. A unique failed link and the pages that reference it are counted separately.

Good means no automated content flags; Review means a difference needs checking; Critical requires a confirmed P0 content or functional finding; Unverified means the pair could not be compared. Always read the denominator: inventoried pages, usable pages and measurable pairs can differ.

Measurements guide the review.

The script does not execute JavaScript or test visual layout, interactions or keyboard behavior. HTTP 200 and high similarity do not prove a successful migration. Linked documents are checked for HTTP availability, not their content or integrity.

02 / Run it yourself

Steps to reproduce the process

Download and extract the kit, then run these commands from its top-level folder. You need Python 3.10 or later and network access to the two websites for collection.

  1. Set the websites and inventory

    Copy the neutral examples, replace the placeholder origins with your source and target, and list the full source URLs in urls.txt. Inventory file paths resolve beside the configuration.

    cp config.example.json config.json
cp urls.example.txt urls.txt
    {
  "name": "My website migration",
  "sourceOrigin": "https://source.example",
  "targetOrigin": "https://target.example",
  "inventories": [{"kind": "urls", "location": "urls.txt"}],
  "includePrefixes": ["/"],
  "excludePrefixes": [],
  "routeMap": {}
}

    For sitemap discovery, use {"kind": "sitemap", "location": "https://your-source.example/sitemap.xml"} instead. Add exact route mappings when target paths differ, such as "/old-page": "/new-page". Record critical journeys and exclusions in scope.md.

  2. Collect a fresh run

    python3 tools/gap_audit.py collect --config config.json --out audit-run-01

    Use a new output directory for each collection. The collector refuses to overwrite an existing run. Open audit-run-01/report.md and analysis.json to inspect the automated baseline.

  3. Verify the differences

    Compare source and target in the browser at matching viewports. Review shared navigation, representative templates, content outliers and required journeys. Record actions, expected and actual results, screenshots, reviewer and time in the review checklist.

    Add supported findings to audit-run-01/reviews.json while keeping its evidenceSha256. Each finding records the affected pages, observation, impact, priority, corrective action, owner or TBD, acceptance test and evidence references. The AI skill includes the finding schema.

  4. Render from the saved evidence

    python3 tools/gap_audit.py render --evidence audit-run-01/evidence.json --reviews audit-run-01/reviews.json --out audit-run-01

    This updates analysis.json and report.md offline. The same saved evidence, review file and toolkit version produce the same report bytes. Preserve those inputs; a fresh crawl or new AI wording may produce different output.

03 / Review & presentation

The AI skill for a PDF audit

The custom skill is pdf-gap-audit, version 1.4.0. Its SKILL.md instructions and supporting files are available as a complete skill package. The full audit kit includes the same skill.

Use it with any capable agent that can read local files, run Python, access the websites, operate a browser and save screenshots. The workflow uses portable files and commands. Your agent does not need a particular vendor's skill system: ask it to read SKILL.md and follow the referenced protocol.

What the actual skill contains

FilePurpose
SKILL.mdThe complete collection → browser review → findings → PDF → verification workflow.
references/A fixed review protocol and the browser evidence schema: coverage, viewports, states, priorities and screenshot records.
scripts/The readiness PDF builder, legacy measured builder and verification helper. The standalone package also includes the Python collector here.
assets/A blank browser manifest; the standalone package also includes configuration, URL and review-checklist starters.
requirements.txtPinned ReportLab, Pillow and pypdf versions for PDF generation and checks.

Build the main readiness PDF after review

python3 -m venv .venv
.venv/bin/python -m pip install -r skills/pdf-gap-audit/requirements.txt
.venv/bin/python skills/pdf-gap-audit/scripts/build_readiness_pdf.py --assessment audit-run-01/readiness.json --validate-only

Prepare the reviewed readiness assessment using the skill’s contract before running these commands. The builder reconciles page/block/variant counts, checks screenshot hashes and crop bounds, embeds supplied records, and writes a PDF plus a build record. The legacy build_pdf.py remains available for measured supporting reports and frozen reproduction. The skill also includes the command to extract text, check page and finding IDs, and render every page with Poppler for inspection. See the full guide for setup and reproduction commands.

What another agent can reproduce

With frozen evidence, reviews, browser records, screenshots, fonts and the same pinned environment, the scripts reproduce the measured report and PDF. A fresh audit repeats the same process and report structure; live site changes, access differences and independent reviewer judgments can change findings. Preserve the selected routes, states and actions so another agent can repeat those checks.
