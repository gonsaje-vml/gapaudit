Run the repair loop yourself

Choose the repaired copy and a new run folder

This example shows the retest after repairs. Before issuing an initial report, make a verification pass through its findings and coverage checklist. The audit-pass guide explains when to repeat a check, when to collect again, and why matching scan results alone do not prove coverage.

  1. Download and extract the retest example

    The ZIP includes the original flawed fixtures, a separate repaired tree, both frozen audit runs, original captures and the toolkit. Start at its README.

  2. Collect a fresh retest

    python3 practice/run_demo.py start --sites repaired --out runs/practice-fixed-01

    The repaired source and target use ports 8861 and 8862 by default; the original exercise uses 8851 and 8852. The command prints the actual addresses. Leave it running for browser review. On Windows use py -3 instead of python3 where appropriate.

  3. Repeat the same acceptance tests

    Use the same routes, matched sizes, download entry points, disclosure actions and keyboard checks as the original audit. Record fixed, still-open, new and unverified outcomes from your own observations. A repair is not closed just because its code changed.

  4. Preserve both runs

    The new folder gets new evidence, snapshots, timestamps and page IDs. The earlier run remains untouched. The repaired fixture is under practice/sites-repaired/; practice/sites/ still demonstrates the original defects.
